# EntityCollection type mismatch in ArticleService + template path resolution

**Date:** 2026-05-15 11:55
**Files:** modules/blog/src/Service/ArticleService.php, modules/init/src/Bootstrap/TemplateResolver.php, modules/init/module.php, bootstrap/app.php
**Severity:** high

## Problem

`/articles` route returned HTTP 500 with two errors:
1. `TypeError: array_filter(): Argument #1 ($array) must be of type array, Marko\Database\Entity\EntityCollection given`
2. After fixing #1: `TemplateNotFoundException: Template 'pages/articles/index' not found.` — templates exist in `templates/` but `ModuleTemplateResolver` only searches `{module}/resources/views/`.

## Root Cause

1. Upstream Marko v0.6.0 changed `Repository::findAll()` return type from `array` to `EntityCollection` (implements `IteratorAggregate`, not `array`). Calling `array_filter()` on an `EntityCollection` throws `TypeError` in PHP 8.5.
2. The project stores all templates in the shared `templates/` directory but `ModuleTemplateResolver` only searches within each module's `resources/views/` directory. No module had templates in its `resources/views/`.

## Solution

**Fix 1 — array_filter with EntityCollection** (`modules/blog/src/Service/ArticleService.php`):
- Added `articlesToArray()` helper: `$articles instanceof \Traversable ? iterator_to_array($articles) : $articles`
- Applied to all 3 methods using `array_filter()` on `findAll()` results

**Fix 2 — template resolution** (`modules/init/src/Bootstrap/TemplateResolver.php`):
- Created `TemplateResolver` decorating the upstream `ModuleTemplateResolver`
- On `TemplateNotFoundException`, falls back to `templates/{template}.php`
- Converts dot notation (`layouts.app`) to directory separators (`layouts/app.php`) for filesystem lookup
- Registered as binding override in `modules/init/module.php`

**Fix 3 — Application instance in container** (`bootstrap/app.php`):
- Added `$app->container->instance(Application::class, $app)` after `initialize()`
- Without this, `$container->get(Application::class)` creates a NEW Application with empty `vendorPath`, breaking path resolution

## Prevention

- When upstream packages change return types (especially `array` → `EntityCollection`), check all callers of `findAll()` and similar DB methods
- New modules should keep templates in their own `resources/views/` directory OR rely on the shared `templates/` fallback
- Always register important singletons (like Application) in the container during bootstrap
